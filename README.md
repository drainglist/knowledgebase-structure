# База знаний по водным видам спорта

Консольный MVP: вопрос на русском языке → тема → категория и условия → подходящие утверждения с источниками. Java 21, Spring Boot 4.1.1, Maven, Spring Data JPA, PostgreSQL. Версии исходного проекта сохранены. Веб-сервер отключён через `spring.main.web-application-type=none`; контроллеров нет.

## Запуск с нуля (Windows, PowerShell)

### 1. Подготовьте окружение

Установите JDK 21, Maven 3.9+ и Docker Desktop. Для Java задайте `JAVA_HOME` на папку JDK, а каталоги `bin` Java и Maven добавьте в `PATH`. Запустите Docker Desktop в режиме Linux-контейнеров и дождитесь готовности Docker Engine.

Откройте новое окно PowerShell и проверьте доступность инструментов:

```powershell
java -version
mvn -version
docker version
docker compose version
```

Java должна иметь версию 21; Maven должен использовать этот же JDK. Команда `docker version` должна показывать сведения и о клиенте, и о сервере.

### 2. Откройте проект и задайте настройки

Все дальнейшие команды выполняйте в одном окне PowerShell:

```powershell
cd C:\polytech\7sem\pd\structure
chcp 65001
[Console]::InputEncoding = [System.Text.UTF8Encoding]::new($false)
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)

$env:DB_PORT = '5432'
$env:DB_URL = "jdbc:postgresql://localhost:$($env:DB_PORT)/water_knowledge"
$env:DB_USERNAME = 'water_knowledge'
$env:DB_PASSWORD = 'root'
```

Если проект находится в другой папке, измените путь в команде `cd`. Вместо `root` задайте собственный локальный пароль. Эти переменные будут использованы и при создании PostgreSQL, и при запуске программы. Они действуют только в текущем окне PowerShell.

Порт `5432` на компьютере должен быть свободен. Если он занят, задайте другое значение `DB_PORT` перед строкой с `DB_URL`, например `5433`.

### 3. Создайте и запустите PostgreSQL

```powershell
docker compose up -d
docker compose ps
```

Compose загрузит образ PostgreSQL 17 и создаст контейнер, пользователя `water_knowledge` и базу `water_knowledge`. Дождитесь статуса `healthy` у сервиса `postgres`, повторяя `docker compose ps`. Отдельно устанавливать PostgreSQL и создавать базу вручную не требуется.

### 4. Соберите и запустите программу

```powershell
mvn verify
```

При первой сборке Maven загрузит зависимости. Дождитесь сообщения `BUILD SUCCESS`, затем запустите собранный jar:

```powershell
java -jar target/structure-0.0.1-SNAPSHOT.jar
```

При интерактивном запуске программа использует кодировку терминала через Java Console; для перенаправленного ввода и вывода используется UTF-8. Настройки кодировки из шага 2 выполняйте до запуска Java в том же окне PowerShell.

Приложение подключится к PostgreSQL, создаст таблицы и загрузит учебные данные. Работа происходит в консоли. После появления приглашения `>` введите, например:

```text
Что нужно новичку для сапбординга?
```

В ответ появятся тема, категория, подходящие утверждения, условия и учебные источники с пометкой DEMO. Затем можно вводить следующие вопросы.

### 5. Завершите работу

В консоли программы введите:

```text
выход
```

После завершения программы остановите базу:

```powershell
docker compose down
```

Данные базы сохранятся в именованном Docker-томе.

## Модель

Все идентификаторы — неизменяемые строковые первичные ключи до 120 символов; у демоданных детерминированные ключи `demo-...`. Новым записям можно назначать UUID в строковом виде.

| Сущность | Данные и связи |
| --- | --- |
| `Topic` | Название, тип SPORT/EQUIPMENT/ENVIRONMENT; 1:N синонимы |
| `TopicSynonym` | Вариант названия; N:1 тема |
| `Statement` | Полный текст, категория, статус; N:1 главная тема; M:N дополнительные темы |
| `StatementCondition` | Тип условия и текст; N:1 утверждение |
| `Source` | Название, адрес документа, признак учебного источника |
| `Evidence` | N:1 утверждение и N:1 источник; фрагмент и позиция в документе |
| `TopicRelation` | Две ссылки на темы и тип USES/DEPENDS_ON/PRACTICED_ON |

Для каждой сущности есть Spring Data JPA репозиторий. Основные связи представлены внешними ключами. Обязательные строки проверяются конструкторами и SQL CHECK/NOT NULL; заданы ограничения длины. Названия тем и адреса источников уникальны, как и пары тема–синоним, утверждение–тип условия, тройки тем–тип отношения и утверждение–источник–позиция. Самоссылка отношения запрещена.

Условные утверждения в демонаборе содержат ограничение в полном тексте и в структурированных условиях. Выдача всегда включает условия, даже если пользователь их не назвал. Модель поддерживает несколько подтверждений на утверждение и несколько утверждений на источник.

`DemoDataSeeder` в одной транзакции добавляет 8 тем, 31 синоним, 6 отношений, 18 утверждений, 13 условий и 18 подтверждений из одного учебного документа. Три основные темы: сапбординг, каякинг, виндсёрфинг. Полный источник — [demo-statements.tsv](src/main/resources/demo-statements.tsv), включённый в jar. Это явно обозначенный учебный набор без внешней проверки; все его утверждения имеют статус DEMO. Устойчивые ключи и проверка существования делают последовательные запуски идемпотентными: существующие записи не перезаписываются. Изменение строки TSV не обновляет уже загруженную запись; для новой версии используйте новый ID или отдельную миграцию.

## Как работает поиск

1. `TextNormalizer` применяет Unicode NFKC, нижний регистр, ё→е; знаки препинания и пробелы превращает в разделители.
2. `KnowledgeSearchService` сопоставляет целые слова/фразы с названиями и синонимами. Сначала рассматривает найденные виды спорта; если их нет — связанные темы. Несколько основных тем требуют уточнения.
3. `SearchVocabulary` читает [search-dictionary.properties](src/main/resources/search-dictionary.properties) в UTF-8. Порядок категорий: SAFETY → EQUIPMENT → GETTING_STARTED → CONDITIONS; при нескольких совпадениях выбирается первая. Слова и порядок можно менять без переписывания алгоритма.
4. Из БД выбираются только VERIFIED, а в деморежиме ещё DEMO. CANDIDATE и REJECTED исключены. Без категории выбирается только GENERAL.
5. Условия сгруппированы по опыту, воде и ветру. Явное несовпадение исключает утверждение; совпадение повышает его позицию. Неупомянутое условие не считается выполненным: утверждение остаётся условным и выводится с ограничением. Противоречивые указания одной группы требуют уточнения.
6. Результат ограничен пятью утверждениями, порядок при равном приоритете устойчив по ID. Снимки данных формируются внутри транзакции; консоль не обращается к ленивым JPA-связям.

Связи тем хранятся для развития базы, но поиск пока не обходит граф и не делает выводов по отношениям. Статус VERIFIED задаётся извне; процедуры проверки фактов в MVP нет. При `DEMO_INCLUDE=false` первоначальный учебный набор не выдаётся.

## Проверки

`mvn verify` запускает интеграционные тесты на H2 в режиме совместимости PostgreSQL. H2 — единственная новая зависимость, только scope=test; она нужна для проверки настоящих JPA-запросов, связей, ограничений и идемпотентности без внешней БД. В рабочий jar H2 не входит.

Тесты проверяют синонимы и нормализацию, границы слов, неоднозначность и неизвестные темы, приоритет основной темы, статусы, условия и их противоречия, ограничение выдачи, сохранность подтверждений, повторную загрузку, SQL-ограничения и отсутствие веб-сервера.

Те же тесты можно запустить на **отдельной пустой тестовой PostgreSQL**:

```powershell
$env:TEST_DB_URL = 'jdbc:postgresql://localhost:5432/water_knowledge_test'
$env:TEST_DB_USERNAME = 'water_knowledge'
$env:TEST_DB_PASSWORD = $env:DB_PASSWORD
mvn test
```

Базу `water_knowledge_test` предварительно создайте с владельцем `water_knowledge`. Тестовый профиль использует **create-drop**, поэтому не указывайте рабочую базу. Без TEST_DB_URL тесты используют H2 и не обращаются к рабочей PostgreSQL.

## Границы MVP

Это словарный поиск, а не понимание произвольного языка. Поддерживаются только внесённые синонимы и формы слов; нет морфологического анализа, исправления опечаток, понимания отрицаний или сложных условий. Например, «не новичку» не интерпретируется как отрицание. Для расширения форм названий нужны новые синонимы в БД. Категория выбирается одна; автоматического сравнения видов спорта нет.

Учебные утверждения не являются проверенными рекомендациями по занятиям спортом. Нет ML, генерации связного ответа, статей, API и интерфейса. Поиск загружает каталог тем и кандидатов выбранной темы в память: для большой базы потребуются индексы поиска и пагинация. Инициализация рассчитана на последовательный запуск одного экземпляра; конкурентный первый запуск не координируется. Hibernate `update` удобен для локального MVP, но версионированные миграции схемы пока не добавлены.

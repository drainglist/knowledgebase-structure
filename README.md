# База знаний по водным видам спорта: переход к RAG

Первый этап новой системы — хранение статьи и её первой версии.
Java 21, Spring Boot 4.1.1, PostgreSQL 17, Maven.

## Что реализовано

- `Document`: название статьи, необязательные автор и HTTP/HTTPS-ссылка,
  идентификатор UUID и дата создания.
- `DocumentVersion`: полный текст первой версии, номер `1`, дата создания
  и контрольная сумма SHA-256 от исходного текста в UTF-8.
- `DocumentService.create(...)` атомарно сохраняет статью и её первую версию.
  При ошибке ни статья, ни версия не сохраняются.
- `DocumentService.get(id)` возвращает сохранённые метаданные и текст первой версии.
- Текст хранится в PostgreSQL `text`, без прежнего ограничения в 4000 символов.
  Пробелы, переносы строк, Unicode и авторская формулировка сохраняются.
- Уникальность `(document_id, version_number)` защищена ограничением БД.
  Изменение текста версии через прикладную модель не предусмотрено.

Исходники новой системы находятся в
`src/main/java/com/polytech/knowledgebase/structure/document/`.
Загрузка файлов и веб-страниц, создание следующих версий, чанки, поисковый
индекс и генерация ответов будут отдельными этапами.

HTTP API и новый пользовательский интерфейс на этом этапе ещё не добавлены.
Прежний дэшборд убран из рабочей сборки; пустая страница с HTTP 404 по `/`
при запущенном приложении ожидаема.

## Запуск

Нужны JDK 21, Maven 3.9+ и Docker Engine с Linux-контейнерами.

```powershell
docker compose up -d
mvn verify
java -jar target/structure-0.0.1-SNAPSHOT.jar
```

Spring Boot и Docker Compose читают `.env` из корня проекта. Файл исключён
из Git; `.env.example` не используется. Без `.env` доступны те же локальные
значения по умолчанию:

| Настройка | По умолчанию |
| --- | --- |
| `DB_HOST` | `127.0.0.1` |
| `DB_PORT` | `5433` |
| `DB_NAME` | `water_knowledge` |
| `DB_USERNAME` | `water_knowledge` |
| `DB_PASSWORD` | `root` |
| `PORT` | `8080` |
| `SERVER_ADDRESS` | `127.0.0.1` |

При необходимости создайте `.env` с нужными `KEY=value`, без кавычек и
`export`. Полный JDBC-адрес можно переопределить через `DB_URL`.
Рабочая схема пока создаётся Hibernate через `DB_DDL_AUTO=update`;
версионированные миграции в этот небольшой этап не входят.

Приложение слушает `127.0.0.1:8080`. Завершение — Ctrl+C.
`docker compose down` останавливает БД, сохраняя её том.

## Проверки

```powershell
mvn verify
```

Тесты используют отдельную временную H2, поэтому для них Docker не нужен.
Проверяются сохранение длинного Unicode-текста без изменений, необязательные
метаданные, атомарность операции, уникальность первой версии, валидация и
отсутствие прежних сущностей и ресурсов дэшборда в активном приложении.

Для проверки на PostgreSQL создавайте **отдельную пустую тестовую базу**.
Тестовый профиль использует `create-drop`; рабочую базу в тестах указывать
нельзя. Пример при стандартных локальных настройках:

```powershell
docker compose exec -T postgres createdb -U water_knowledge rag_storage_test
mvn verify '-Dspring.datasource.url=jdbc:postgresql://127.0.0.1:5433/rag_storage_test' '-Dspring.datasource.username=water_knowledge' '-Dspring.datasource.password=root'
docker compose exec -T postgres dropdb -U water_knowledge rag_storage_test
```
